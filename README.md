# WAVEBREAK

A cel-shaded arcade boat racing game on an infinite procedural ocean. Four racers,
three laps, one circuit marked out on open water by a glowing green line that rides
the swell.

Everything you see and hear is generated by the code in this repository. There are no
model files, no textures, no HDRIs and no audio samples — every mesh is `BufferGeometry`
built at runtime, every texture is drawn to a canvas or evaluated in a shader, and every
sound is synthesised with the Web Audio API.

```bash
npm install
npm run dev
```

Then open the printed URL. That is the whole setup.

boost. Landing flat off a crest kills your speed — land nose-down.

## Art direction

One palette, committed to across water, sky, hulls, riders and UI: **Tropic Ink**.
High-saturation turquoise and cobalt water, cream and coral UI, deep indigo ink lines
rather than black. It lives in `src/core/Palette.ts` and nothing outside that file
contains a colour literal.

The rendering is entirely non-photorealistic:

- **Ramp lighting.** A `NearestFilter` ramp texture with four hard bands, cool-tinted in
  shadow and warm in the top step. No interpolation anywhere in the diffuse path.
- **Two line systems.** Inverted-hull ink shells give silhouettes; a screen-space Sobel
  pass over a normal/depth G-buffer gives interior lines. They are explicitly prevented
  from doubling up — the shells write `edgeMask = 0` so the Sobel pass skips them.
- **Constant-width outlines.** The hull shell is pushed in clip space and divided by the
  viewport, so an ink line is the same pixel width at 2m and at 200m.
- **Banded specular and fresnel rim** on every hull and rider, so silhouettes separate
  from the water.
- **Fake reflection only.** A hand-drawn matcap stands in for the environment. There is
  no cubemap probe, no IBL and no PBR material anywhere in the project.

## The ocean

The water is the largest system in the game and gets the most attention.

- Six **Gerstner waves** — two long swells, two mid-frequency shaping waves, two chop
  layers — summed in the vertex shader with analytic normals and a Jacobian term used to
  find crests.
- The wave definition lives in exactly one place, `src/ocean/waveConfig.ts`. The GLSL is
  *generated* from that TypeScript array, and `src/ocean/GerstnerCPU.ts` evaluates the
  same maths on the CPU (inverse-solving the horizontal displacement) for buoyancy, wake
  ribbons, gates and buoys. The physical water and the visible water cannot drift apart.
- The surface is a camera-following radially-graded mesh, snapped to a grid so vertices
  do not swim, giving an infinite ocean with no seam and no visible tiling.
- Colour is banded by wave height and by lighting, with `fwidth()`-based steps so the
  band edge is exactly one pixel wide at any distance.
- Foam is a real system: crest foam driven by wave compression, a hull ring driven by
  proximity, a persistent wake ribbon per boat that spreads and dissipates while
  re-sampling the wave height every frame, and spray particles on landings and hard turns.

## Layout

See `ARCHITECTURE.md` for the full contract. In short:

```
src/
  Game.ts          composition root — owns and orders every subsystem
  core/            engine, input, camera rig, palette, procedural textures, RNG
  render/          cel material, inverted-hull outlines, post-process composer
  ocean/           wave contract, CPU sampler, water surface, foam/wake/spray
  sky/             gradient dome, cel clouds, sun and stylised flare
  boat/            procedural hull, buoyancy, arcade physics
  rider/           in-code skeleton, skinning and procedural animation
  race/            circuit spline, race director, AI racers
  ui/              canvas-2D HUD, minimap, screens
  audio/           Web Audio synthesis
  debug/           harness hooks
```

### Screenshot harness

Visual claims in this project are checked against captured frames rather than against
assumptions about what the code does. `tools/shoot.mjs` boots the game in headless
Chromium, steps the simulation deterministically to an exact moment, and captures
retina-resolution PNGs from a set of named camera rigs.

```bash
node tools/shoot.mjs --shots chase,lowwater,bow,rider,aerial,horizon,wake,pack \
                     --time 12 --out shots/review
```

Because the simulation is seeded (`?seed=`) and stepped at a fixed `1/60`, a given
`(seed, time)` pair always produces the same frame — so a difference between two runs is
a real regression, not noise. The harness exits non-zero on any console error or page
error, which means a shader that fails to compile can never slip through unnoticed.

It needs a Chromium for Playwright:

```bash
npx playwright install chromium
```

## Performance

Targeting a locked 60fps at `devicePixelRatio` 2 on Apple silicon:

- Adaptive pixel ratio with hysteresis — the renderer trades resolution for frame time
  slowly enough that the change is invisible.
- Instanced clouds, gates, buoys and spray; shared geometry across the four boats and
  the four riders.
- One draw call for the ocean; a fullscreen *triangle* rather than a quad in every post
  pass; render targets allocated once and reused.
- No per-frame allocation in any `update()` — scratch vectors live at module scope.

## State of the build

An honest scorecard, judged against captured frames rather than against whether the code
runs. "Working" is the floor here, not the goal.

| Subsystem | Where it is | What is still short |
| --- | --- | --- |
| Ocean surface | ~85% | Deep-band colour drifts slightly cool in the far field |
| Racing line, gates, buoys | ~85% | Line reads faint from a low chase angle |
| Camera rigs | ~85% | — |
| HUD, minimap, screens | ~85% | Results screen needs a real capture pass |
| Cel / ink pipeline | ~80% | Interior Sobel lines are subtle on hull panel breaks |
| Sky and clouds | ~75% | The sun and its flare sit outside every gameplay framing |
| Boat geometry | ~75% | Chine crease does not read at gameplay distance; foredeck is a large low-detail surface |
| Riders | ~75% | Limbs are smooth tapered tubes; hands are geometric |
| Wake foam | ~65% | Still reads flat — hard-edged and correctly white, but without enough internal form to bend over the swell |
| Race logic / AI | ~75% | Personalities are implemented but under-verified in motion |
| Audio | untested | Synthesised and wired, but never heard — the harness runs muted |

Verified: `npm run typecheck` clean, `npm run build` clean, 20 shader programs compile,
~106 draw calls and ~219k triangles in a four-boat race, no console or page errors beyond a
favicon 404.

Three findings worth recording, because each one came from looking at a frame rather than
reading the code:

1. **Every colour in the game was double-decoded.** `Palette.ts` built colours as
   `new THREE.Color(hex).convertSRGBToLinear()`, but three's colour management already
   decodes hex to linear on construction. Coral's green channel fell from 0.047 to 0.0036;
   the ink collapsed to near-black. Most "muddy" and "washed out" review notes traced back
   to that one line.
2. **All eight harness camera angles were rendering the same view.** `mode = 'free'` fell
   through to `updateChase()`, so every art judgement made before that was made on frames
   that did not show what they claimed.
3. **The rider could never reach the yoke.** Instrumenting the rig showed the hands sitting
   0.46 m short of the grips — a measurable fault, not an aesthetic one, and invisible in
   any code review.
